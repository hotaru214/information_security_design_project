# 开源项目横向对比与自研系统创新性分析

## 1. 答辩结论先行

本项目的创新性不应表述为“某个单点功能世界首创”。在安全领域，ATT&CK 映射、日志检测、流量分析、威胁情报、案件管理、攻击仿真等能力，很多成熟开源项目都已经覆盖了一部分。

更准确的表述是：

> 现有开源项目通常分别侧重主机告警、网络流量监控、威胁情报管理、取证时间线、案件协同或攻击仿真。本系统面向企业内网攻击溯源这一课程场景，将多源 Event 标准化、ATT&CK 攻击步骤识别、时间窗口关联、攻击图重建、证据回查、攻击者画像和 APT/TTP 相似性匹配整合为一个轻量级闭环，从而实现从原始日志到攻击路径与攻击者画像的自动化分析。

答辩时重点讲：

```text
不是替代大型平台，
而是在“小型企业内网靶场 + 多源日志 + 自动溯源”场景下，
做了端到端、可解释、可复核、可演示的组合式创新。
```

## 2. 调研对象选择

本项目横向对比以下典型开源项目：

| 项目 | 选择原因 |
| --- | --- |
| Wazuh | 代表主机安全监控、SIEM/XDR、规则告警和 ATT&CK 映射 |
| Security Onion | 代表网络安全监控、Zeek/Suricata、PCAP 和威胁狩猎 |
| Arkime | 代表大规模 PCAP 存储、索引和网络会话检索 |
| Sigma | 代表通用日志检测规则格式 |
| Timesketch | 代表数字取证时间线和自动化 analyzer |
| OpenCTI | 代表威胁情报知识图谱和 STIX 模型 |
| MISP | 代表威胁情报共享、IOC 关联和 Galaxy 知识库 |
| TheHive | 代表安全事件响应、案件协同和 observable 管理 |
| MITRE Caldera | 代表基于 ATT&CK 的攻击仿真和对抗演练 |

这些项目都很成熟，因此对比重点不是“谁强谁弱”，而是看它们和本系统的目标是否相同、输出是否相同、是否天然覆盖课程要求的完整闭环。

## 4. 各开源项目能力与差异

### 4.1 Wazuh

Wazuh 是开源 SIEM/XDR 平台，重点能力包括：

- 主机 agent 数据采集。
- 日志 decoder 和规则检测。
- 文件完整性监控、漏洞检测、合规检查等。
- 告警与 MITRE ATT&CK tactic / technique 映射。
- Dashboard 中展示 ATT&CK 视图。

官方文档中，Wazuh 的 MITRE ATT&CK 模块主要用于将 Wazuh 生成的告警映射到 ATT&CK tactics 和 techniques，帮助分析员理解威胁性质。

与本系统差异：

| 维度 | Wazuh | 本系统 |
| --- | --- | --- |
| 核心目标 | 终端安全监控与告警 | 企业内网攻击行为溯源 |
| 输入 | Agent 日志、规则告警 | A/B/C 统一 EventOut |
| 输出 | 告警、ATT&CK 视图、仪表盘 | AttackStep、攻击链、攻击图、画像 |
| 关联方式 | 以规则告警和 dashboard 聚合为主 | 以时间窗口、主机/IP 映射和图关系为主 |
| 证据回查 | 支持告警到日志 | 每个 AttackStep 绑定数据库 evidence_event_ids |

可讲创新点：

> Wazuh 偏“发现告警”，本系统偏“把告警和事件串成攻击过程”。我们不是只说某台机器出现了 T1059，而是进一步分析它与初始入侵、横向移动、数据收集和 C2 之间的因果关系。

### 4.2 Security Onion

Security Onion 是网络安全监控平台，重点能力包括：

- Suricata NIDS 告警。
- Zeek 或 Suricata 协议元数据。
- Full packet capture。
- 文件分析。
- Host visibility、日志管理、Hunt、Dashboards、Case Management。

它的强项是网络侧可见性和威胁狩猎，尤其适合分析 PCAP、Zeek、Suricata 告警和网络元数据。

与本系统差异：

| 维度 | Security Onion | 本系统 |
| --- | --- | --- |
| 核心目标 | 网络安全监控、威胁狩猎 | 多源攻击链溯源 |
| 网络能力 | 很强，覆盖 Zeek、Suricata、PCAP | 使用 C 模块解析后的网络 Event |
| 主机行为 | 有 endpoint visibility，但不是本项目这种统一事件模型 | 主机日志、网络流量统一进入 Event V2 |
| 分析方式 | 分析员在 Hunt / Alerts 中调查 | D 自动生成 AttackStep 和攻击图 |
| 适合场景 | 企业级监控平台 | 课程靶场轻量化演示 |

可讲创新点：

> Security Onion 更像一个强大的监控和狩猎平台，需要分析员基于 alerts、Zeek 和 PCAP 进一步调查。本系统则把这些线索抽象成统一 Event 后，自动关联成 ATT&CK 攻击步骤和主机间攻击图。

### 4.3 Arkime

Arkime 是开源网络流量分析和 packet capture 系统，重点能力包括：

- 存储和索引标准 PCAP。
- 快速检索网络 session。
- 查看、下载、回溯会话数据。
- 支持 API 获取 PCAP 数据和 JSON session 数据。

它适合回答：

```text
某个 IP 和谁通信过？
某段时间有哪些 HTTP/DNS/TLS session？
某个连接的原始包是什么？
```

与本系统差异：

| 维度 | Arkime | 本系统 |
| --- | --- | --- |
| 核心目标 | 网络包捕获、索引、检索 | 攻击行为溯源 |
| 数据重点 | PCAP / session | 主机日志 + 网络事件 + 行为事件 |
| ATT&CK 映射 | 不是核心功能 | 核心输出 |
| 攻击链 | 需要人工分析 session | 自动从 AttackStep 建图 |
| 画像 | 不是重点 | 提取工具、脚本、C2、TTP |

可讲创新点：

> Arkime 能很好地回答“网络上发生了什么连接”，但本系统进一步回答“这些连接在攻击链中意味着什么”。

### 4.4 Sigma

Sigma 是通用日志检测规则格式，类似“日志世界的 YARA/Snort 规则思想”。它的重点是：

- 用统一 YAML 规则描述日志检测逻辑。
- 规则可以转换到不同 SIEM 查询语言。
- 社区维护大量检测规则。
- 适合检测工程和威胁狩猎。

与本系统差异：

| 维度 | Sigma | 本系统 |
| --- | --- | --- |
| 定位 | 检测规则格式 | 完整分析系统 |
| 输入 | 日志字段 | EventOut 列表 |
| 输出 | 匹配某条规则 | AttackStep、攻击链、画像 |
| 上下文关联 | Sigma 有 correlation 规范，但本身不是平台 | D 内置时间窗口、图路径和 evidence |
| 前端展示 | 无 | 有攻击图和分析报告 |

可讲创新点：

> Sigma 是规则表达标准，本系统借鉴规则检测思想，但进一步做了跨源上下文关联和攻击链图生成。

### 4.5 Timesketch

Timesketch 是数字取证时间线分析平台，重点能力包括：

- 将取证事件索引到时间线。
- 搜索、标注、保存视图。
- Analyzer 自动 enrich timeline。
- 支持 Sigma Analyzer 给事件打标签。

与本系统差异：

| 维度 | Timesketch | 本系统 |
| --- | --- | --- |
| 核心目标 | 取证时间线分析 | 企业内网攻击链溯源 |
| 数据组织 | Timeline / Sketch | EventOut / AttackStep / AttackGraph |
| 自动分析 | Analyzer 标注事件 | D 自动生成攻击步骤和图路径 |
| 重点视角 | 时间线 | ATT&CK 生命周期 + 主机关系图 |
| 证据 | 时间线事件 | AttackStep evidence_event_ids |

可讲创新点：

> Timesketch 强在时间线取证，本系统则在时间线基础上增加了 ATT&CK 阶段建模和主机关系图，使输出更贴合“攻击链溯源”。

### 4.6 OpenCTI

OpenCTI 是威胁情报管理平台，核心设计是知识图谱：

- 节点表示 threat actor、malware、tool、attack pattern、observable 等实体。
- 边表示实体之间的关系。
- 数据模型基于 STIX 2.1。
- 适合管理威胁组织、IOC、TTP、报告和情报关系。

与本系统差异：

| 维度 | OpenCTI | 本系统 |
| --- | --- | --- |
| 核心目标 | 威胁情报知识管理 | 本地事件攻击溯源 |
| 图的含义 | 情报实体关系图 | 攻击行为发生图 |
| 输入 | 情报报告、IOC、STIX、连接器 | 本地 EventOut |
| 输出 | 情报实体和关系 | 攻击步骤、攻击路径、画像候选 |
| APT 关系 | 管理已知组织和 TTP | 根据本地攻击行为计算相似性 |

可讲创新点：

> OpenCTI 管的是“已知情报世界的关系”，本系统建的是“本次攻击事件中真实发生的关系”。我们再用本地画像库把本次攻击行为和已知 APT TTP 做相似性匹配。

### 4.7 MISP

MISP 是开源威胁情报共享平台，重点能力包括：

- 存储、共享、关联 IOC。
- 支持事件、属性、对象、标签、taxonomy。
- MISP Galaxy 包含威胁组织、工具、恶意软件、ATT&CK 等知识。
- 自动关联 indicator，例如 hash、domain、IP、CIDR、fuzzy hash 等。
- 支持 STIX 等格式导入导出。

与本系统差异：

| 维度 | MISP | 本系统 |
| --- | --- | --- |
| 核心目标 | 威胁情报共享与关联 | 攻击事件溯源分析 |
| 关联对象 | IOC、attribute、event、galaxy | EventOut、AttackStep、主机/IP/C2 |
| 自动攻击链 | 不是核心目标 | 核心目标 |
| 证据关系 | 情报事件与属性 | 数据库事件 ID 到攻击步骤 |
| 适合场景 | 多组织情报共享 | 本地靶场/企业内网攻击回放 |

可讲创新点：

> MISP 更偏情报共享和 IOC 关联，本系统更偏把本地日志中的攻击过程重建出来。我们可以吸收 MISP 的威胁情报思想，但系统主线是攻击链生成。

### 4.8 TheHive

TheHive 是安全事件响应和案件协同平台，重点能力包括：

- Alert triage。
- Case 管理。
- Observable 管理。
- 分析任务、评论、报告。
- 和 Cortex analyzer 等工具联动。
- 支持调查流程协同。

与本系统差异：

| 维度 | TheHive | 本系统 |
| --- | --- | --- |
| 核心目标 | SOC 案件处置和协同 | 自动攻击链关联 |
| 用户 | 分析员、事件响应团队 | 课程项目演示和自动分析 |
| 输入 | Alerts、observables、case 信息 | 标准 EventOut |
| 输出 | Case、任务、observable、报告 | AttackStep、攻击图、画像 |
| 自动化程度 | 依赖分析员处置流程 | 自动生成攻击路径 |

可讲创新点：

> TheHive 解决的是“案件怎么协同处置”，本系统解决的是“怎么从多源事件自动还原攻击过程”。两者可以互补，但本项目重点是 D 的关联算法。

### 4.9 MITRE Caldera

MITRE Caldera 是基于 ATT&CK 的攻击仿真平台，重点能力包括：

- 自动化 breach-and-attack simulation。
- 使用 agent 在目标环境执行 adversary abilities。
- 基于 ATT&CK profile 组织攻击行为。
- 用于红队演练、防御验证和安全评估。

与本系统差异：

| 维度 | Caldera | 本系统 |
| --- | --- | --- |
| 核心目标 | 主动模拟攻击 | 被动分析已经发生的攻击 |
| 数据来源 | 平台执行的攻击 operation | B/C/A 采集解析后的日志和流量 |
| ATT&CK 用法 | 指导攻击动作执行 | 解释检测到的攻击步骤 |
| 输出 | Operation、ability 执行结果 | AttackStep、攻击图、证据、画像 |
| 角色 | 红队/紫队仿真工具 | 蓝队溯源分析工具 |

可讲创新点：

> Caldera 是“产生攻击行为”，本系统是“从日志和流量中还原攻击行为”。一个偏仿真，一个偏溯源。

## 5. 本系统创新性拆解

### 5.1 创新点一：面向多源日志的统一 Event 模型

本系统将不同来源的数据统一成 Event V2：

```text
Windows EVTX
Sysmon
Linux auth
Linux audit
PCAP
Zeek
Firewall
WAF
```

其中关键设计是：

```text
source = 证据来源
event_type = 行为类型
```

例如：

```text
source=network_pcap, event_type=http_request
source=firewall, event_type=network_connection
source=waf, event_type=http_request
source=sysmon, event_type=process_start
```

这样 D 的规则就不需要针对每种日志格式分别写一套，而是基于统一行为语义分析。

答辩表述：

> 我们将数据来源和安全行为解耦建模，让不同采集源产生的同类行为可以进入统一关联流程，降低了多源日志融合分析的复杂度。

### 5.2 创新点二：从事件到 ATT&CK AttackStep 的中间层

很多平台直接从日志生成告警，而本系统设计了 AttackStep 中间层：

```text
EventOut -> AttackStep -> AttackGraph / Report / Attribution
```

AttackStep 包含：

```text
stage
technique_id
technique_name
source_host / source_ip
target_host / target_ip
timestamp
description
evidence_event_ids
case_id
```

好处：

1. 将底层日志转成安全语义。
2. 将 ATT&CK 映射和攻击图解耦。
3. 前端、报告、画像模块都可以复用 AttackStep。
4. 每个攻击步骤都能回查证据。

答辩表述：

> AttackStep 是我们在 Event 和攻击图之间设计的语义中间层，它把原始事件抽象为可解释的 ATT&CK 攻击行为，并保留 evidence_event_ids 支撑回溯。

### 5.3 创新点三：时间窗口上下文关联

D 不是只看单条日志，而是使用时间窗口把多条事件组合成一个攻击步骤。

例子一：横向移动

```text
源主机前 10 分钟可疑执行
  + 内网到内网远程服务连接
  + 目标主机后 10 分钟登录/进程/服务行为
  => Lateral Movement / T1021
```

例子二：数据外传

```text
前 30 分钟敏感文件读取/压缩
  + 内网到外网大流量上传
  => Exfiltration / T1041
```

例子三：初始入侵

```text
外部 IP 访问 DMZ Web
  + WAF/Firewall/HTTP 异常语义
  + 目标主机后续 process_start
  => Initial Access / T1190
```

答辩表述：

> 我们使用时间窗口关联，将进程、登录、文件、网络等不同来源的证据组合起来，避免只依赖单条日志做孤立判断。

### 5.4 创新点四：攻击链与攻击图双层表达

攻击链强调顺序：

```text
Initial Access -> Execution -> Lateral Movement -> Collection -> C2
```

攻击图强调实体关系：

```text
attacker -> web-server -> win10-jump -> core-server
                             \
                              -> c2-server
```

本系统同时保留两种表达：

| 表达 | 作用 |
| --- | --- |
| 攻击链 | 用于讲清楚攻击过程 |
| 攻击图 | 用于展示主机、IP、C2 之间的关系 |
| evidence | 用于回查每一步依据 |

图算法思想：

```text
节点 = 主机 / 攻击者 / C2 / 外部 IP
边 = AttackStep
方向 = source -> target
路径 = 图中的攻击传播路线
```

答辩表述：

> 攻击链可以看作攻击图中的一条路径，攻击图则是多条路径和分支活动的叠加。本系统用图结构同时表达主线攻击和分支行为。

### 5.5 创新点五：case_id 批次隔离

真实实验中可能反复导入多批数据，如果所有事件直接混在一起，D 可能把不同数据集的事件误连起来。

因此系统支持：

```text
一个 case_id = 一次攻击事件 = 一批完整证据
```

D 会按 case 分组分析：

```text
case01 的事件只和 case01 关联
case02 的事件只和 case02 关联
```

答辩表述：

> 我们引入 case_id 批次隔离机制，在允许多批数据共存的同时，避免跨案例误关联，提高攻击链分析的可靠性。

### 5.6 创新点六：攻击者画像与 APT/TTP 相似性评分

D 不止生成攻击链，还会提取攻击者画像：

```text
ATT&CK 技术编号
攻击阶段序列
工具
脚本
配置文件
注册表键
文件 hash
外部 IP
域名
C2 基础设施
```

然后和本地 APT 画像库做相似性匹配。

评分设计：

```text
final_score = 0.7 * rule_score + 0.3 * semantic_score
```

其中：

```text
rule_score =
  0.55 * technique_score
  + 0.20 * tool_score
  + 0.15 * sequence_score
  + 0.10 * infra_score
```

| 分数 | 含义 |
| --- | --- |
| `technique_score` | ATT&CK 技术编号覆盖度 |
| `tool_score` | 工具重合度 |
| `sequence_score` | 攻击阶段序列相似度，使用 LCS 思想 |
| `infra_score` | C2 / 基础设施标签相似度 |
| `semantic_score` | 画像文本 token cosine 相似度 |

答辩表述：

> 我们的画像匹配不是简单 IOC 命中，而是综合 ATT&CK 技术、工具、行为顺序、基础设施标签和语义文本相似度，输出 TTP 相似性候选。

### 5.7 创新点七：谨慎归因，避免无证据硬猜

攻击者身份溯源不能说成“百分百确认某组织”。因此系统输出的是：

```text
TTP similarity match only, not confirmed attribution.
```

当没有有效事件、攻击步骤或 C2 证据时：

```text
attribution_status = insufficient_evidence
apt_matches = []
```

答辩表述：

> 我们没有把画像匹配包装成绝对身份确认，而是输出基于证据的行为相似性候选，这更符合安全分析中的严谨性。

## 7. E 数据示例说明

在 E 数据中，系统导入：

```text
事件数：47775
主机映射：9
批次：e_final
```

识别出的关键节点：

```text
attack-external
web-server
win10-jump
core-server
c2-server
```

关键攻击边：

```text
Initial Access:
attack-external 10.10.10.10 -> web-server 10.10.20.10

Lateral Movement:
web-server 10.10.20.10 -> win10-jump 10.10.30.10

Collection:
win10-jump 10.10.30.10 -> core-server 10.10.30.20

Command and Control:
win10-jump 10.10.30.10 -> c2-server 10.10.10.20
```

注意：

```text
win10-jump -> core-server
```

这一步没有强行判成横向移动，因为它的真实语义是 HTTP GET 内部文件资源，更符合：

```text
Collection / T1005 Data from Local System
```

这个例子可以体现本系统的一个优点：

> 系统不是只根据 IP 和端口机械连线，而是根据行为语义决定 ATT&CK 阶段。

## 8. 答辩推荐讲法

### 8.1 如果老师问：这些开源项目不是也能做吗？

可以回答：

> 是的，很多单点能力在成熟开源项目中都存在。比如 Wazuh 支持主机告警和 ATT&CK 映射，Security Onion 和 Arkime 在网络流量分析方面很强，OpenCTI 和 MISP 适合做威胁情报管理，TheHive 适合案件协同，Caldera 适合攻击仿真。我们的创新点不是替代这些大型平台，而是面向本次企业内网攻击溯源任务，把多源事件标准化、攻击步骤识别、攻击图重建、证据回查和画像匹配整合成一个轻量闭环。

### 8.2 如果老师问：算法创新在哪里？

可以回答：

> 我们没有只做单条规则告警，而是先将多源日志统一成 EventOut，再通过时间窗口关联把主机行为、认证日志和网络连接组合成 ATT&CK AttackStep。随后将 AttackStep 建模为有向攻击图，用图路径表达攻击传播过程。画像部分则结合 ATT&CK 技术覆盖度、工具重合度、行为序列 LCS 相似度、基础设施标签和文本相似度进行 APT/TTP 候选匹配。

### 8.3 如果老师问：攻击链和攻击图是什么关系？

可以回答：

> 攻击链是攻击图中的一条路径，强调攻击按什么顺序推进；攻击图是多条路径和分支行为的整体叠加，强调攻击者、主机、核心服务器和 C2 之间的关系。比如 E 数据中，win10-jump 既访问 core-server 收集数据，又连接 c2-server 通信，这种分支更适合用攻击图表达。

### 8.4 如果老师问：APT 匹配是不是能确定攻击者？

可以回答：

> 不能直接确定真实身份。我们的身份溯源是基于可观测证据做 TTP 相似性匹配，输出的是候选组织和相似原因，不是法律意义上的确认归因。系统保留了匹配到的技术、工具、C2 基础设施和 evidence_event_ids，便于分析员进一步复核。

### 8.5 如果老师问：和 OpenCTI/MISP 的画像有什么区别？

可以回答：

> OpenCTI 和 MISP 更偏威胁情报知识管理，适合存储和共享已知 IOC、APT、工具、恶意软件和情报关系。我们的系统是从本地日志和流量中自动还原这次攻击过程，再把提取到的工具、脚本、C2、TTP 与本地画像库比较。也就是说，它们偏“情报库”，我们偏“从事件到溯源结果的自动分析”。

## 10. 可放进 PPT 的创新性总结

### 10.1 一句话版本

> 本系统面向企业内网攻击溯源场景，构建了从多源 Event 标准化到 ATT&CK 攻击步骤识别、攻击图重建、证据回查和攻击者画像匹配的轻量级分析闭环。

### 10.2 三点版本

1. 多源融合：统一主机日志、网络流量、防火墙、WAF 等数据为 EventOut。
2. 可解释关联：通过时间窗口和 ATT&CK 规则生成 AttackStep，并保留 evidence_event_ids。
3. 溯源画像：基于工具、脚本、C2、TTP 序列和基础设施标签进行 APT/TTP 相似性匹配。

### 10.3 五点版本

1. `source` 和 `event_type` 解耦，提升多源事件规则复用性。
2. 设计 AttackStep 中间层，将底层事件转成安全语义。
3. 使用时间窗口关联主机行为、认证日志和网络连接。
4. 使用有向图表达攻击者、主机、核心服务器和 C2 的关系。
5. 使用规则相似度与文本相似度结合的方法生成攻击者画像候选。

## 11. 创新性边界说明

答辩时建议主动说清楚边界，这样更显得专业：

```text
我们不声称 ATT&CK 映射、流量分析、威胁情报或攻击图是单点首创；
我们的创新性在于面向课程靶场的组合式集成和自动化闭环。
```

这样可以避免被老师追问“Wazuh/OpenCTI/Security Onion 不是也有吗”时陷入被动。

更稳的说法：

> 我们参考了现有开源安全工具的能力边界，但没有简单堆功能，而是围绕“企业内网攻击行为溯源”这个目标重新组织数据模型和分析流程。系统以 EventOut 为统一输入，以 AttackStep 为安全语义中间层，以攻击图和 evidence_event_ids 为可解释输出，最后扩展到攻击者画像与 TTP 相似性分析。

### 13.2 我们的创新点简洁表达

1. 多源统一：把 Windows/Linux 主机日志、网络流量、防火墙、WAF 等统一为 EventOut。
2. 自动关联：通过时间窗口、host_map、内外网方向和 ATT&CK 规则，把事件关联成 AttackStep。
3. 图化溯源：将攻击步骤转换成有向攻击图，展示攻击者、Web 服务器、跳板机、核心服务器和 C2 的关系。
4. 证据画像：每个攻击步骤保留 evidence_event_ids，并进一步提取工具、脚本、C2、TTP 序列做 APT 相似性匹配。

> 相比开源项目各自聚焦某一类安全能力，本系统把多源事件标准化、攻击链关联、攻击图重建、证据回查和攻击者画像整合成了一个面向企业内网攻击溯源的轻量闭环。

## 14. 可直接讲的开源项目对比段落

### 14.1 与 Wazuh 对比

Wazuh 更像一个主机安全监控和告警平台，它可以采集终端日志，并把告警映射到 MITRE ATT&CK 技术上。但它的核心输出仍然是告警和安全事件视图。本系统在这个基础上更进一步，关注的是如何把多条日志和网络事件串成完整攻击过程。也就是说，Wazuh 更擅长回答“哪里产生了告警”，而我们的系统更强调回答“攻击者从哪里进来、经过哪些主机、访问了什么核心资源、最后连接了哪个 C2”。

### 14.2 与 Security Onion / Arkime 对比

Security Onion 和 Arkime 在网络流量分析方面很强，尤其适合查看 Zeek 日志、Suricata 告警、PCAP 会话和原始网络包。但它们更偏网络侧调查，需要分析员自己结合主机日志去还原攻击过程。本系统的区别是，我们把网络流量解析成统一 Event 后，再和主机进程、登录、文件、注册表等事件一起关联，自动生成 ATT&CK 攻击步骤和攻击图。因此我们不是只展示“有哪些连接”，而是进一步解释“这些连接在攻击链中代表什么行为”。

### 14.3 与 OpenCTI / MISP 对比

OpenCTI 和 MISP 更偏威胁情报管理，适合存储 IOC、APT 组织、工具、恶意软件、攻击技术和情报关系。它们的优势是管理已知情报，但不是专门从本地日志中自动还原一次攻击链。本系统的方向相反：我们先从本地事件中重建攻击过程，再提取工具、脚本、C2、域名、TTP 序列等画像特征，最后与本地 APT 画像库进行相似性匹配。所以它们偏“情报知识库”，我们偏“事件驱动的溯源分析”。

### 14.4 与 TheHive / Timesketch 对比

TheHive 和 Timesketch 都很适合安全分析人员做调查。TheHive 偏案件管理和协同处置，Timesketch 偏取证时间线分析。它们能帮助分析员整理证据，但通常还需要人工判断攻击步骤之间的关系。本系统的特点是把这些关联逻辑前置到 D 模块中，用规则、时间窗口和图算法自动生成 AttackStep 和攻击图，让系统直接给出可解释的攻击链结果。

### 14.5 与 Caldera 对比

Caldera 是 ATT&CK 攻击仿真平台，主要用于主动执行攻击动作，帮助蓝队验证检测能力。我们的系统不是产生攻击，而是分析已经发生的攻击。它们的方向正好相反：Caldera 是从 ATT&CK 技术出发去模拟攻击，本系统是从日志和流量出发，反向还原攻击者使用了哪些 ATT&CK 技术。

### 14.6 总结段

综合来看，这些开源项目在各自方向都比我们的课程系统更成熟，但它们通常不是为“小型企业内网攻击溯源演示”这个场景专门设计的。本系统的价值在于把课程要求中的多个环节串成闭环：先由 B/C 解析多源数据，再由 A 统一入库，D 生成攻击步骤、攻击链和攻击图，最后前端展示证据和画像结果。它的创新点是场景化、组合式和可解释，而不是单个功能的孤立创新。
