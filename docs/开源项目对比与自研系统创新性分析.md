# 开源项目对比与自研系统创新性分析

## 1. 调研目的

本项目要求“通过对比其他开源项目，验证自研系统的创新性”。这里的“创新性”不应理解为某个单点功能从未出现过，而应理解为：在企业内网攻击溯源这一具体场景下，系统如何把多源数据统一、攻击链关联、攻击图重建、证据回查和攻击者画像匹配整合成一个轻量、可解释、可演示的分析闭环。

因此，本节选择 Wazuh、Security Onion、Arkime、Sigma、OpenCTI、MISP、TheHive、Timesketch 等典型开源项目作为对比对象，分析它们的核心能力、适用场景以及与本系统的差异。

## 2. 总体结论

现有开源项目大多在某一类能力上非常成熟，例如：

- Wazuh 更偏主机侧日志检测、告警和 MITRE ATT&CK 映射。
- Security Onion 更偏网络安全监控、Zeek/Suricata/PCAP 分析和威胁狩猎。
- Arkime 更偏大规模网络会话检索和全流量回溯。
- Sigma 更偏可移植检测规则表达。
- OpenCTI 和 MISP 更偏威胁情报知识管理与 IOC/TTP 关联。
- TheHive 更偏安全事件响应和案件协同。
- Timesketch 更偏取证时间线分析和自动化 analyzer。

本系统的创新性不在于替代上述大型平台，也不是声称某一个能力完全独创，而是在小学期企业内网靶场场景下，将这些能力中与“攻击行为溯源”最相关的部分抽象出来，形成了一个轻量级端到端流程：

```text
多源日志/流量
  -> 统一 Event V2
  -> ATT&CK 攻击步骤识别
  -> 攻击链排序
  -> 攻击图建模
  -> 证据回查
  -> 攻击者画像与 APT/TTP 相似性匹配
```

## 4. 自研系统的创新点

### 4.1 面向多源日志的统一事件建模

本系统设计了统一的 Event V2 数据结构，将 Windows 事件日志、Sysmon、Linux auth/audit、Zeek、PCAP、防火墙、WAF 等异构数据统一为同一种事件格式。

其中一个关键设计是将 `source` 和 `event_type` 解耦：

```text
source     = 证据来源
event_type = 安全行为
```

例如：

```text
source=waf, event_type=http_request
source=firewall, event_type=network_connection
source=network_zeek, event_type=network_connection
```

这样做的好处是，同一种攻击行为可以来自不同采集源，D 的关联规则不需要为每一种日志来源重复写一套逻辑，提高了规则复用性和系统扩展性。

推荐表述：

> 本系统将数据来源与安全行为解耦建模，使不同采集源产生的同类行为可以进入统一关联流程，降低了多源日志融合分析的复杂度。

### 4.2 证据保真的攻击步骤关联

传统检测系统往往先产生告警，再由分析员回查原始日志。本系统在生成每一个攻击步骤时，都保留 `evidence_event_ids`，并且这些 ID 指向数据库内部事件主键。

因此，攻击链中的每个结论都可以反查到完整 Event 和 `raw_log`：

```json
{
  "stage": "Lateral Movement",
  "technique_id": "T1021",
  "description": "web-server connected to office-pc through SMB remote service",
  "evidence_event_ids": [3, 2, 4]
}
```

推荐表述：

> 本系统在攻击链生成过程中保留证据闭环，每个 ATT&CK 阶段结论都绑定数据库事件 ID，使攻击路径不仅可展示，而且可复核、可追溯。

### 4.3 时间窗口上下文关联

系统不是只依赖单条事件判断攻击步骤，而是把事件放入前后时间窗口中分析。例如横向移动并不只看一条 SMB/RDP/SSH 连接，而是综合判断：

```text
源主机前一段时间是否出现可疑命令执行
  + 源主机是否连接目标主机远程服务端口
  + 目标主机随后是否出现登录成功、进程启动或服务创建
  => 横向移动 / T1021
```

这种方式能把孤立事件组合成更接近真实攻击过程的行为步骤。

推荐表述：

> 本系统采用时间窗口上下文关联方法，将进程、认证、网络连接和文件行为联合判断，从而提升对横向移动、C2 外联、数据外传等复合攻击行为的识别能力。

### 4.4 攻击链与攻击图双层表达

系统同时输出两种视角：

- 攻击链：强调时间顺序和 ATT&CK 阶段演进。
- 攻击图：强调主机、IP、C2 节点之间的关系。

例如系统可以从事件中自动得到类似路径：

```text
外部攻击 IP -> Web 服务器 -> 办公主机 -> 核心服务器 -> C2 服务器
```

这种双层表达让系统既能回答“攻击按什么顺序发生”，也能回答“攻击者在网络里如何移动”。

推荐表述：

> 本系统将时序攻击链和实体攻击图结合起来，既保留攻击阶段的时间演进，又能展示攻击者在主机、内网 IP、外部 C2 之间的移动路径。

### 4.5 案例级隔离分析

系统支持在同一套数据库和接口中存放多个攻击案例，但 D 侧关联分析会按 `case_id` 分组，避免不同攻击案例之间发生误关联。

这对课程实验尤其重要，因为调试和演示阶段可能反复导入不同批次数据。如果没有案例隔离，系统可能把两个无关实验中的事件错误地连成一条攻击链。

推荐表述：

> 本系统引入案例级隔离机制，在支持多批次、多场景数据共存的同时，保证攻击链关联只在同一案例内部进行，降低跨场景误关联风险。

### 4.6 攻击者画像与 APT/TTP 相似性匹配

在攻击链基础上，系统进一步提取攻击者指纹，包括：

- 攻击工具：如 `powershell.exe`、`reg.exe`、`curl`、`wevtutil.exe`
- 脚本与配置文件：如 `.ps1`、`.sh`、`.json`、`.conf`
- 注册表持久化键值
- 文件哈希
- 外部 IP、域名、C2 端口
- ATT&CK 技术序列

随后系统使用本地 APT 画像库进行相似性匹配，综合考虑：

```text
ATT&CK 技术覆盖度
工具/脚本重合度
攻击阶段顺序相似度
基础设施标签相似度
语义相似度
```

最终分数设计为：

```text
final_score = 0.7 * rule_score + 0.3 * semantic_score
```

推荐表述：

> 本系统在攻击链结果上进一步构建攻击者画像，并使用规则匹配与语义相似度结合的方法进行 APT/TTP 相似性分析，相比单纯 IOC 命中或单点 ATT&CK 映射，更能反映攻击行为整体特征。

## 5. 与开源项目相比的综合创新性

需要注意，本系统不应声称“ATT&CK 映射”“攻击图”“威胁情报关联”等能力完全由本项目首创。很多成熟开源平台已经具备其中一部分能力。

本系统的创新性应强调“组合式创新”和“场景化创新”：

1. 面向企业内网攻击溯源，而不是通用 SIEM 或单纯流量检索。
2. 面向小学期靶场轻量部署，而不是依赖大型安全平台。
3. 从统一 Event 到攻击链、攻击图、证据回查、攻击者画像形成闭环。
4. 将主机日志、认证日志、网络流量、注册表、文件行为放在同一分析流程中。
5. 输出结果可解释，每一步都有证据 ID 支撑。

推荐总述：

> 现有开源项目通常分别侧重日志告警、网络流量检索、威胁情报管理或案件协同。本系统的创新性不在于单一功能首创，而在于面向企业内网攻击溯源任务，将多源 Event 标准化、ATT&CK 攻击步骤识别、证据回查、攻击图路径重建和 APT/TTP 相似性匹配整合为轻量级闭环，实现了从原始日志到攻击路径与攻击者画像的自动化分析流程。

## 6. 答辩时可以这样讲

如果老师问：“这些功能很多开源平台不是也有吗？”

可以回答：

> 是的，单个能力在很多成熟开源项目中都有体现，例如 Wazuh 支持 ATT&CK 映射，Security Onion 和 Arkime 在网络流量分析方面很强，OpenCTI 和 MISP 更适合做威胁情报管理。我们的创新点不是替代这些大型平台，而是针对本次企业内网攻击溯源任务，把多源日志标准化、攻击链关联、攻击图重建、证据回查和攻击者画像匹配集成到一个轻量系统中，让它能够在课程靶场里自动生成可解释、可复核的攻击路径。

如果老师问：“你们的算法创新在哪里？”

可以回答：

> 我们没有只做单条规则告警，而是把事件放入时间窗口中进行上下文关联。例如横向移动需要结合源主机可疑执行、内网远程服务连接和目标主机登录事件共同判断；C2 和外传则结合内外网方向、可疑端口、重复连接、流量大小和前序数据收集行为。最后再基于 ATT&CK 技术、工具、阶段顺序和基础设施标签做 APT/TTP 相似度评分。

如果老师问：“攻击者身份溯源是不是能确定真实攻击组织？”

可以回答：

> 不能直接确认真实身份。我们这里的身份溯源是基于公开 APT 画像和本地威胁情报库做 TTP 相似性匹配，输出的是“行为相似度”而不是法律意义上的归因结论。系统会保留匹配到的技术、工具、C2 基础设施和证据事件，供分析员进一步研判。
