C 主机日志数据获取说明（apt29_day1 / ctu13_s2）
================================================

【apt29_day1 主机日志】
- 原始包已清理，需先重新下载:
  python -c "import sys; sys.path.insert(0,'scripts'); from fetch_dataset import fetch; open('data/datasets/apt29/day1/apt29_evals_day1_manual.zip','wb').write(fetch('https://raw.githubusercontent.com/OTRF/detection-hackathon-apt29/master/datasets/day1/apt29_evals_day1_manual.zip', timeout=300))"
  （或直接浏览器下载: https://github.com/OTRF/detection-hackathon-apt29 -> datasets/day1/apt29_evals_day1_manual.zip）
- 来源: https://github.com/OTRF/detection-hackathon-apt29
  路径 datasets/day1/apt29_evals_day1_manual.zip
- 解压后为单个 JSON 文件:
  apt29_evals_day1_manual_2020-05-01225525.json
  内容为 Windows Sysmon / SecurityEvent 主机日志（JSON 行格式）

【ctu13_s2 主机日志】
- 无公开主机日志。CTU-13 只发布网络侧数据（bro 日志 / binetflow / pcap）
  和恶意样本行为说明（场景目录下的 README.md / botnet-capture-*.json）。
- 主机侧只能引用官方 README 对 Neris 的行为描述做对照，网络侧已完成。

【处理与交付】
- 主机日志解析出的事件与网络侧事件**用同一个 case_id 入库**（如 apt29_day1），
  构成完整案例供 D 跨源关联。最简单方式：数据管理页一次上传
  combined_zeek.log + 主机 JSON，后端自动分发 C/B 解析器并统一打标。
- 命令行方式: python scripts/reset_import_export.py --name apt29_day1 --events <事件JSON>
