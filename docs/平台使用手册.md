# 平台使用手册 —— 恶意攻击行为溯源分析系统

> 面向全组（A/B/C/D/E/F）的标准操作手册。所有命令在仓库根目录执行，Windows Git Bash / PowerShell 通用（路径分隔符按需调整）。

## 一、平台总览

```text
原始证据(PCAP/Zeek/auditd/EVTX/防火墙日志)
        │
        ▼
[解析层]  C: backend/parsers/network (--profile)   B: backend/b_host_parser (run_parse.py)
        │  产出 Event V2 统一事件（19 字段 + 批次标签 detail.batch_id）
        ▼
[契约校验] validate_events / validate_eventout（不合规直接阻断）
        │
        ▼
[存储层]  A: FastAPI + SQLite (data/attack_trace.db)
        │  POST /api/events/import   GET /api/events   /api/hosts
        ▼
[分析层]  D: backend/analysis (correlate_events -> attack_steps -> attack_graph -> attack_paths)
        │  输入=带数据库 id 的 EventOut，evidence_event_ids 回指证据
        ▼
[展示层]  F: frontend/index.html（时间线/攻击链/报告/统计）
```

**核心约定**：一批数据一个库（防串链）、事件带 `detail.batch_id`、字段名以
[docs/Event-V2-FINAL.md](Event-V2-FINAL.md) 为唯一权威。

## 三、标准操作流程（SOP）：从一批数据到攻击链

### 第 1 步：打开平台（四种方式，按场景选择）

**方式 1：标准方式（验收演示默认）—— 后端同源托管前端**

```bash
.venv/Scripts/python -m uvicorn backend.main:app --port 8000
```

浏览器打开 http://127.0.0.1:8000/ —— 前端、事件 API、攻击链 API 同源直连，
页面为 **live 模式**（显示当前库内批次数据，无演示徽章）。
健康检查 `/health`，接口文档 `/docs`。
前提：库里有想展示的批次（用第五步的 `reset_import_export.py` 导入）。

**方式 2：双批次对比演示（8000 主库 + 8001 演示库）**

```bash
# 窗口1：主库（如 ctu13_s2 批次）
.venv/Scripts/python -m uvicorn backend.main:app --port 8000
# 窗口2：演示库（如 e_case01 靶场批次）——先重置导入该批
python scripts/reset_import_export.py --name e_case01 --events out/e_case01_events.json --hosts data/hosts_e_case01.csv
.venv/Scripts/python -m uvicorn backend.main:app --port 8001
```

前端 api.js 对 8000/8001 都走同源直连：8000 看一个批次、8001 看另一个批次，
切浏览器标签即切案例，无需改代码。注意两个端口各连各的库文件，
切换批次时先停对应实例再跑 reset 脚本。

**方式 3：前端独立部署（前后端分开起）**

```bash
.venv/Scripts/python -m http.server -d frontend 8030        # 窗口1：前端
.venv/Scripts/python -m uvicorn backend.main:app --port 8000 # 窗口2：后端
```

访问 http://127.0.0.1:8030 —— api.js 会回落调用 http://127.0.0.1:8000 的后端
（CORS 已放开）。适合前端单独调试。

**方式 4：断网兜底（mock 演示模式）**

不起后端，直接浏览器打开 `frontend/index.html`（或方式 3 只起前端）——
前端 2 秒内探测后端失败，自动回退内置 mock 数据并在角落显示
"演示模式（后端未连接）"徽章；也可点页脚"进入演示模式（mock 数据）"按钮。
验收保底：即使现场网络/后端故障，演示依然完整可讲。

**停止平台**：关闭对应窗口即可；若窗口已关但端口仍被占（孤儿进程）：
`reset_import_export.py` 每次运行会自动清理 8000 端口残留。

### 第 2 步：解析原始数据

**C 网络侧（PCAP / Zeek / 防火墙日志）——用 profile，零手工参数：**

```bash
# E 靶场（4 个抓包点 pcap + 防火墙 filterlog，一次喂入）
python -m backend.parsers.network data/network_logs/e_case01/attack-to-web.pcap data/network_logs/e_case01/web-to-win10.pcap data/network_logs/e_case01/win10-to-core.pcap data/network_logs/e_case01/win10-to-c2.pcap "E-work/raw/firewall/filter.log" --profile e_case01 --out out/e_case01_events.json --summary-json out/e_case01_summary.json

# 其余批次同理：--profile case01 / case02 / apt29_day1 / ctu13_s2
```

**B 主机侧（EVTX / auditd）**：入口 `backend/b_host_parser/run_parse.py`，
参数与产出见 [backend/b_host_parser/README.md](backend/b_host_parser/README.md)。

### 第 3 步：入库（C/B -> A）

```bash
python scripts/post_events.py out/e_case01_events.json --sync-hosts data/hosts_e_case01.csv
```

（导入前自动契约自检；回拉后自动 EventOut 校验 + round-trip 比对，全部通过才算成功。）

### 第 4 步：导出 EventOut 给 D（一批一库）

```bash
python scripts/reset_import_export.py --name e_case01 --events out/e_case01_events.json --hosts data/hosts_e_case01.csv
# 产出: data/sample_events/e_case01_eventout.json（自动重置库->导入->打 batch_id->导出）
```

### 第 5 步：D 关联分析

```bash
python scripts/run_correlation_demo.py          # 内置样例演示
# 或代码内: correlate_events(events, host_map, internal_networks) -> attack_steps
#           build_attack_graph(steps) / find_attack_paths(steps) / build_attribution_profile(...)
```

### 第 6 步：F 前端展示

`frontend/index.html` 直接用浏览器打开（或 `python -m http.server -d frontend 8080` 后访问
http://127.0.0.1:8080）；数据面板消费 `data/sample_events/*_eventout.json` 与
`out/*_summary.json`（Dashboard 汇总）。

## 五、批次规则（2026-09-10 定案：一个案例 = 一个批次 = 全部证据）

1. **完整导入**：一次攻击事件的**全部证据**（主机日志 + 网络流量 + 防火墙日志）
   用**同一个 case_id** 导入——B/C 解析、D 跨源关联都依赖同案例多源共存。
   反例：把主机日志和网络流量拆成两个批次，D 就无法把"Web 入侵"和"恶意进程"串成一条链。
2. **上传方式**：数据管理页一次多选上传全部文件（自动分派 B/C 解析器）；
   同 case_id 的多次上传会**追加**到同一案例。
3. **删除批次**：批次列表"删除"按钮（或 DELETE /api/ingest/{case_id}），
   用于纠正误导入——会删除该案例全部事件，不可恢复。
4. **查看**：页眉下拉按 case_id 切换；D 的 attack-chain/attribution/analysis 均支持 ?case_id=。
5. 单批完全重置仍可用 `reset_import_export.py`（清库重导，id 从 1 起）。

## 六、契约与校验卡点

| 校验 | 位置 | 作用 |
| --- | --- | --- |
| `validate_events` | 解析器输出（19 字段） | 字段集/枚举/severity/UTC+8/占位值阻断 |
| `validate_eventout` | D 的输入（19+id） | 加 id 唯一正整数校验 |
| `collect_warnings` | 非阻断 | 当前仅 host 为 IP 字符串（待后端放宽可空后归零） |
| `tests/test_contract_guard.py` | CI 守卫 | data/sample_events/ 下所有 *_eventout.json 自动受检 |

source 枚举（2026-09-09 扩充）：`windows_evtx / sysmon / linux_auth / linux_audit /
network_pcap / network_zeek / firewall / waf`。source=证据来源，event_type=行为类型；
来源专有字段（action/rule_id/attack_type 等）一律放 detail。

## 七、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 导入 422 | 看响应 detail 的 Pydantic 错误定位（post_events.py 会自动打印）；常见：缺 +08:00 时区、host 为空、detail 非对象 |
| CLI NameError: os | 使用了旧版本代码——拉取最新 main |
| 端口 8000 被占用 | 孤儿 uvicorn 残留：`reset_import_export.py` 会自动清理，或手动 taskkill |
| 契约自检不合规 | 按打印的问题行修数；禁止 unknown/空串/0 占位，缺失一律 null |
| D 关联出跨批次链条 | 违反批次隔离——确认只加载了单批 EventOut，且 detail.batch_id 过滤生效 |
