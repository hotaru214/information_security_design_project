## 五、关键风险（评审时必须说清）

1. **长任务**：解析几分钟级 → 必须异步 + 任务状态，不能用同步 HTTP（否则触发前端超时，正是之前修过的 P0 那类问题）。
2. **外部工具链依赖**：B 依赖 `python-evtx`（本次才发现本地 venv 漏装），C 依赖 `scapy`；验收机需按 `requirements.txt` 完整安装。
3. **原始数据形态**：E 的原始数据是"多目录多文件"（evtx + auditd txt + pcap），上传需要打包（zip/tar）与解包策略、路径白名单，否则易被当成路径穿越攻击面。
4. **契约一致性**：B/C 输出必须仍过 `validate_events`；D 的 `evidence_event_ids` 必须指向**入库后的真实 `events.id`**（当前是"先入库再关联"才成立）。
5. **case 与批次混用**：项目既定约定是"一批一库"（`scripts/reset_import_export.py` 注释），在线化后若多 case 共库，需先解决报告/攻击链的 case 口径（见需求 1 的 ④），否则会出现"溯源看 case01、报告看全库"。
