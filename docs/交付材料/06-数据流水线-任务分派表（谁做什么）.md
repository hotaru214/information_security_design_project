> 判定标准**只用 `分工.md` 最初的六人角色定义**（§6–§12），不作新的分工发明。

> |---|---|---|
> | **A 组长/集成** | 后端架构、数据库、API、代码合并 | FastAPI 主工程 |

## 二、按最初分工看：你原本管什么 → 这次多出什么

### A（组长/集成：后端架构、DB、API、合并）
- **原本就有**：`events`/`hosts` 表、事件 CRUD 与导入接口、`/api/attack-chain`、`/api/analysis`。
- **这次多出（仍在"数据流动"职责内）**：`GET /api/cases`（②）、`AnalysisRequest.case_id`（④）、上传接口（⑤）、编排接口（⑧）、任务状态（⑫）、把 `attack_steps`/`analysis_tasks` 两张表**真正建起来**（⑪）——注意这两张表是 A 最初就规划的，不算新职能。
- **越界检查**：无。恰好是"数据流动"的延伸。

### B（主机日志解析）
- **原本就有**：EVTX/Sysmon/auth/audit 解析、异常预标记、契约合规。
- **这次多出**：把解析包成**可被后端调用**的入口（⑨），输入由"写死的 E 目录"改为"路径入参"。
- **越界检查**：无。B 的本职就是"能导入主机日志并生成结构化事件"；服务化只是换调用方式。

### C（网络流量解析）
- **原本就有**：PCAP/Zeek/防火墙解析，`analyze_paths()` 已是函数。
- **这次多出**：让它能安全地被后端调用（⑩）——不打印、不抛裸异常、返回结构化结果。
- **越界检查**：无。原文"然后提交给 A 的后端"，说明 C 只负责产出。

### D（安全分析：关联 + ATT&CK）
- **原本就有**：9 阶段检测器、建图、BFS 路径、证据绑定、画像与 TTP 相似度。
- **这次多出**：定义 **AttackStep 的持久化结构**（⑪ 的结构部分）+ 确认 `correlate_events()` 可被 A 直接调用。
- **越界检查**：**注意**——"建表与写入"归 A，D 只出结构定义；如果让 D 直接写库，就越出了"D 管算法、A 管 DB"的原始边界。算法本身**零改动**。

### E（靶场/数据：准备攻击数据、靶场、验证）
- **原本就有**：8 节点靶场、攻击剧本、取证原始数据（`E-work/raw/**`）。
- **这次多出**：定**原始数据打包规范**并交付样例包（一套数据=一个 zip）+ 用新流程复现既有结果做回归验证。
- **越界检查**：无。这正是"准备攻击数据 + 验证"。

### F（展示/LLM：前端可视化）
- **原本就有**：4 个页面（Dashboard/时间线/攻击链/报告）+ LLM 报告 + 本次的身份溯源。
- **这次多出**：case 下拉（③）、报告/攻击链带 case（④ 前端部分）、**新增两个页面**（⑥ 数据导入、⑬ 数据解析与分析）。
- **越界检查**：⚠️ **原文明确"F 做非常轻量的界面，我会限定只有四页"** —— 新增两个页面**超出了最初的分工约定**，需要团队/组长认可（建议：作为"数据管理"折叠区或单独 Tab，并在报告里注明是扩展）。

## 五、排期（按最初分工的执行顺序）

**阶段一：验收前 P0（约 1 人日）**
- A：`GET /api/cases`（②）+ `AnalysisRequest.case_id`（④接口侧）
- F：case 下拉（③）+ 攻击链/报告带 case（④前端侧）

**阶段二：验收后第一批 P1（约 3–4 人日，两条并行）**
- 上传链路：E 出 zip 规范 → A 做上传接口 → F 做上传页
- 解析链路：B/C 服务化 → A 做编排 + 任务状态 → F 做分析页

**阶段三：P1 收尾（约 1.5–2 人日）**
- D 出 AttackStep 持久化结构 → A 建 `attack_steps`/`analysis_tasks` 并写入 → E 用新流程回归验证

**阻塞关系**：F 的三个界面分别等 A 的接口；A 的编排等 B/C 服务化 + 上传接口 + 落库能力；A 建表等 D 的结构定义。

## 硬底线（避免重复踩坑）

1. **解析必须异步**：本地实测 B 解析 E 靶场产 47,055 条事件数分钟级，同步 HTTP 必超时（= 之前修过的 P0 同类问题）。
2. **上传必须设防**：大小上限、扩展名白名单（`.evtx/.txt/.log/.json/.pcap/.pcapng/.zip`）、解包防路径穿越、解析异常不得 500 泄漏堆栈。
3. **依赖要装全**：`python-evtx`、`requests`、`scapy` 都在 `requirements.txt` 里，本地 venv 曾漏装（本次排查时才发现）。
4. **契约守卫不能绕**：B/C 输出必须过 `validate_events`；D 的 `evidence_event_ids` 必须指向**入库后的真实 `events.id`**（先入库、后关联顺序不可颠倒）。
