## 一、标准事件JSON结构

```json
{
  "timestamp": "2020-09-09 21:18:23.627951+08:00",
  "host": "MSEDGEWIN10",
  "source": "windows_evtx",
  "event_id": 4625,
  "event_type": "login_failure",
  "user": "IEUser",
  "process": "chrome.exe",
  "src_ip": null,
  "dst_ip": null,
  "dst_port": null,
  "protocol": null,
  "logon_type": 2,
  "session_id": null,
  "cmdline": null,
  "detail": {
    "substatus": "0xc000006a",
    "substatus_desc": "密码错误",
    "failure_reason": "%%2313",
    "workstation": "MSEDGEWIN10"
  },
  "description": "用户 IEUser 登录失败（交互式登录(本地键盘)，原因: 密码错误）",
  "anomaly_flags": [],
  "severity": 0,
  "raw_log": "<Event xmlns=... （原始XML，截断2000字符）>"
}
```

## 二、字段说明与约束

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| timestamp | str | 必填 | **统一UTC+8**，格式 `YYYY-MM-DD HH:MM:SS[.微秒]+08:00`。所有数据源（含C的流量）同此时区 |
| host | str | 必填 | 主机名（Windows取evtx的Computer字段）。D的关联引擎按它join |
| source | str | 必填 | `windows_evtx` / `sysmon` / `linux_auth` / `linux_audit` |
| event_id | int | 必填 | 原始事件ID，方便溯源回原始日志 |
| event_type | str | 必填 | 见下方枚举，不许私造新词 |
| user | str | 可空 | 登录/进程涉及的用户 |
| process | str | 可空 | 进程可执行文件名（不含路径），如 `chrome.exe` |
| src_ip | str | 可空 | 源IP。**本地登录= null**（Windows原始值是"-"）；可能是IPv6 |
| dst_ip | str | 可空 | 目的IP，**仅Sysmon ID 3网络连接有值**，其余事件null |
| dst_port | int | 可空 | 目的端口，**仅Sysmon ID 3有值**（4624里的IpPort是源端口，放detail.src_port） |
| protocol | str | 可空 | 传输协议"tcp"/"udp"，**仅Sysmon ID 3有值**，与C的网络事件同构 |
| logon_type | int | 可空 | Windows登录类型（2本地/3网络/10 RDP...） |
| session_id | str | 可空 | `"主机名:LogonId"`；4624登录时生成，Day2用4634注销配对成完整会话 |
| cmdline | str | 可空 | 命令行（Sysmon ID 1 / 4688 才有） |
| detail | dict | 必填(可为{}) | 各类日志的特有字段（substatus、父进程、文件路径等） |
| description | str | 必填 | 中文一句话描述，前端列表直接展示 |
| anomaly_flags | list | 必填 | 异常预标记规则名，无异常=[]（Day2由B的规则填） |
| severity | int | 必填 | 0正常 / 1低 / 2中 / 3高 |
| raw_log | str | 必填 | 原始XML/日志行片段（≤2000字符），前端"查看证据"用 |

**三条硬规矩**：
1. **键必须17个全在**，没值的填 `null`，不许删键（A建表唯一依据）。
2. **空值统一 null**：Windows日志里的"-"在入库前必须转成null。
3. **时间统一UTC+8**：evtx里是UTC，解析器负责转；C的流量时间戳也要对齐。

## 三、event_type 枚举（与C共用）

`login_success` 登录成功 / `login_failure` 登录失败 / `logoff` 注销 / `process_create` 进程创建 / `file_create` 文件创建 / `registry_set` 注册表键值 / `network_connect` 主机网络连接 / `account_created` 新建账号 / `log_cleared` 日志被清 / `sudo_exec` sudo提权 / `file_access` 文件访问

> C同学的网络事件从这套词里取（如 dns/http 相关若要加，会议上一起定）。
