# 测试分析报告——公开数据集上的恶意攻击行为溯源分析实验

> 负责人：成员C（网络流量解析模块） ｜ 任务书测试要求(1)：收集互联网中企业内网攻击行为数据集，针对数据集环境开展恶意攻击行为溯源分析

## 1. 实验目的与总体口径

自研系统的检测规则此前在自造样例数据（case01/case02）上验证。本实验将系统放到**互联网公开的、
由第三方产出且带 ground truth 的真实攻击数据集**上运行，检验三件事：

1. 解析器对真实环境数据格式（非自造格式）的兼容能力；
2. 检测规则在真实流量中的命中与误报情况；
3. 与数据集自带 ground truth 的对照结果。

口径说明：本实验为**网络侧单源实验**（主机侧 Sysmon/auditd 由 B 模块另行覆盖）；
APT29 评估采用其公开 Sigma 规则的 ATT&CK tag 作为 ground truth。

## 2. 数据集一：CTU-13 场景 2（Neris 僵尸网络）

- **来源**：Stratosphere IPS Lab（CVUT Prague），CTU-Malware-Capture-Botnet-43
- **规模**：Zeek conn/dns/http 日志全集 356 万行（571MB）；实验取**前 10 万行×3 日志子集**
  （约 25 分钟流量窗口，139,195 个会话）
- **Ground truth**：官方 README 明确感染主机为 147.32.84.165（Windows XP "SARUMAN"，Neris 僵尸网络）
- **下载方式**：`python scripts/fetch_dataset.py --ctu CTU-Malware-Capture-Botnet-43`（脚本已入库）

### 2.1 适配改造（本实验产出的工程改进）

| 改造点 | 内容 |
| --- | --- |
| CSV 列名别名 | parse_connection_csv 支持 binetflow 的 StartTime/SrcAddr/Sport/DstAddr/Dport/Proto/TotBytes/Dur/Label 列 |
| 小数秒时间戳 | `_parse_ts` 补 2011/08/10 08:47:35.5 等 4 种格式 |
| 数据集标签 | dataset_label 进 detail，供检出结果与标签对账 |
| **误报修复** | 谷歌分析 utmcmd= 参数撞 Web 攻击正则 → 加负向断言（真实数据上告警 1354→16） |
| **广播过滤** | 子网广播 147.32.255.255:4444/UDP 噪声不再触发可疑端口告警 |
| **新规则 cc_rotation** | 同源对同端口窗口内轮询 ≥5 个不同外部主机（CC 列表轮询，T1071）——直接来自本实验的观察 |

### 2.2 检出结果（对照感染主机 ground truth）

| 规则 | 命中感染主机相关(TP) | 未涉及(TP/FP外) | 说明 |
| --- | --- | --- | --- |
| suspicious_port (T1571) | **8** | 2 | 感染主机向 7 个不同外部 IP 的 6667/IRC C2 连接，全部命中 |
| cc_rotation (T1071) | **1** | **0** | 感染主机 25 分钟轮询 7 个 C2 —— 新规则零误报 |
| exfiltration (T1048) | 0 | 18 | 背景窗口内的大文件下载（正常软件更新类流量） |
| c2_beacon (T1071) | 0 | 11 | 正常主机的周期性外联（补丁/时间同步类） |
| dns_tunnel (T1071.004) | 0 | 8 | 正常域名的高熵长子域名（CDN 类） |
| brute_force / 横向 / Web攻击 | 0 | 20 | 背景流量中的正常远程服务与含 cmd= 参数的请求 |
| **合计** | **9** | **59** | 窗口内背景流量占比 >98% |

### 2.3 结论

- 面向**攻击链行为**的规则（CC 轮询、IRC C2 端口）在真实数据上**精确命中感染主机**；
- 面向**单流特征**的规则（大流量、周期性、熵值）在背景流量为主的窗口中误报较多——
  这定量地证明了**跨源事件关联（D 模块）的必要性**：单流告警需与主机侧异常相互印证后才能定性；
- 该数据集验证了自研系统对真实 Zeek 日志的完整解析与事件化能力（139,195 会话全部合规入库）。

## 3. 数据集二：APT29 ATT&CK Evaluations Day1（OTRF）

- **来源**：OTRF detection-hackathon-apt29（Mordor 项目），企业域环境下的 APT29 攻击模拟
- **规模**：合并 Zeek JSON 流 613 会话；host 为 bobs.bigwheel.local 等，内网 10.0.0.0/16
- **Ground truth**：仓库 26 条公开 Sigma 规则的 ATT&CK tag，共 **19 个技术**
  （T1005, T1045.002, T1048.003, T1070.004, T1082, T1087.002, T1088.002, T1112, T1113,
  T1115, T1134.002, T1140, T1204.002, T1546.015, T1547.001, T1548.002, T1552.004, T1560.001, T1571）
- **下载方式**：`python scripts/fetch_dataset.py --apt29`

### 3.1 适配改造

新增**合并 JSON 流解析**：该数据集的 combined_zeek.log 为每行一个 JSON（@stream 字段区分
conn/dns/http、下划线键名 id_orig_h），与常规 TSV/嵌套 JSON 均不同。解析器现支持三种 Zeek 形态。

### 3.2 检出结果（对照 Sigma 规则技术清单）

| 我们的检出 | 技术 | 与 ground truth 对照 |
| --- | --- | --- |
| 48 条内网横向连接（SMB/RDP/WinRM） | T1021 | 场景事实吻合（APT29 day1 即域内横向渗透）；Sigma 规则未给网络侧 tag，属规则集覆盖差异 |
| 4 条数据外传（受害机 10.0.1.4 → 192.168.0.x C2 基础设施） | T1048 | **父技术命中** T1048.003（WebDAV 外传 over C2） |
| footprintdns.com 长标签 DNS 查询 | T1071.004 | **GT 外发现**：footprintdns.com 是 APT29 真实 C2 域名，Sigma 规则集未覆盖该行为，系统自动标记待复核 |
| 10.0.1.4 → 10.0.1.6 高频连接 | T1110 | 待人工复核（可能是横向操作重试） |

精确技术级交集为 0、父技术级命中 1（T1048）；未命中的 15 个 ground truth 技术
（注册表持久化、凭据转储、文件收集等）**均为主机侧行为**，落在 B 模块（Sysmon）的职责范围内——
这定量说明了任务书要求"主机日志+主机行为+网络流量**多源**融合"的原因：单看网络侧无法覆盖攻击链全貌。

## 4. 局限与下一步

1. **单源局限**：网络侧独立覆盖不了主机侧行为，APT29 实验的 15/19 未命中技术需要 B 的
   Sysmon JSON 适配完成后做多源联合评估（已与 B 协调）。
2. **子集口径**：CTU-13 用 10 万行子集（全量 356 万行内存受限）；全量评估需要后端分批入库后做。
3. **关联缺失**：D 的关联引擎尚未交付，本实验评估口径为"告警集合 + 攻击阶段时间线"，
   链路级溯源（入侵点→横向→外传的自动串联）待 D 接入后补评。
4. 复现方式：所有数据可用 `scripts/fetch_dataset.py` 重新下载，解析命令见
   `backend/parsers/network/README.md` 第 1 节。
